## Problem

ADR 0001 defines a minimal `dms/{dmId}` and `dms/{dmId}/messages/{messageId}` schema; that baseline is insufficient to build a conversation list, unread badges, message previews, or a paginated thread. Five questions are unresolved: (1) when the parent doc is created; (2) where unread counts live server-side; (3) whether the send path uses a batch or sequential writes; (4) which query and index power the conversation list; (5) whether `senderDisplayName` is denormalized. Without answers the Flutter Engineer will produce code that fails silently on web, loses badge counts across restarts, and makes N+1 reads on every message render.

---

## Constraints

- `dmId` = `min(uidA, uidB) + '_' + max(uidA, uidB)` — constructed in `data/` only (ADR 0001).
- `areFriends()` costs 2 `get()` calls — message rules must NOT call it (10-call budget). The DM create rule does NOT call `areFriends()` either; the friends gate is enforced client-side in `ChatRepositoryImpl.sendMessage`, which must verify `users/A/friends/B.status == 'accepted'` and `users/B/friends/A.status == 'accepted'` by reading from Firestore before issuing any write.
- Web: `FieldValue.serverTimestamp()` resolves after rule evaluation — no `== request.time` on any DM field.
- Web: `WriteBatch` combining a message `set()` and a DM `update()` causes a rule evaluation conflict — sequential writes only.
- Cloud Functions unavailable on Spark plan. Group chat and session chat out of scope.

---

## Options

### SD1 — DM document creation
| Option A | Option B | Option C |
|---|---|---|
| **Chosen.** Lazy — `SetOptions(merge: true)` on first send | Eager — `set()` when conversation opens | Unconditional `set()`; overwrite race on concurrent first sends |

Idempotent, sidesteps `resource == null` denial on non-existent docs, zero empty conversation entries.

### SD2 — Unread count storage
| Option A | Option B | Option C |
|---|---|---|
| **Chosen.** `unreadCounts: Map<String, int>` on parent doc; `FieldValue.increment(1)` on send; zeroed on open | Client-side only via `flutter_secure_storage` | `dms/{dmId}/unread/{uid}` subcollection per participant |

Rides the parent doc already streamed for the list (zero extra reads); `FieldValue.increment` handles concurrent updates without read-modify-write.

### SD3 — Message send write sequence
| Option A | Option B | Option C |
|---|---|---|
| **Chosen.** Two sequential `await` calls: (1) message set, (2) DM update | `WriteBatch` combining both | Message write only; DM update via Cloud Function |

Option B silently fails on web (rule evaluation conflict); Option C blocked by Spark plan. Step-2 partial failure yields a stale preview — the message persists and heals on next send.

### SD4 — Conversation list query
| Option A | Option B | Option C |
|---|---|---|
| **Chosen.** Stream `dms` where `participantUids array-contains uid`, `orderBy lastMessageAt desc` (Index 11) | Stream all message subcollections client-side | `users/{uid}/dmConversations` mirror subcollection |

One composite index, zero extra write paths. Option B is read-expensive; Option C adds a three-write send sequence and a desync-prone mirror.

### SD5 — `senderDisplayName` denormalization
| Option A | Option B |
|---|---|
| **Chosen.** Denormalize at send time from local auth state — zero Firestore reads | Resolve from `users/{senderUid}` on render — N+1 reads |

Consistent with ADR 0001's `hostDisplayName` pattern; staleness acceptable at MVP since Profile Edit is future work.

---

## Decision

Lazy doc creation (`SetOptions(merge: true)`), server-side `unreadCounts` map (`FieldValue.increment`), and denormalized `senderDisplayName` eliminate extra reads at the cost of eventual consistency. Two sequential writes replace the batch because `WriteBatch` silently fails on web; the conversation list streams `dms` filtered by `participantUids array-contains` and ordered by `lastMessageAt desc` (Index 11). No `== request.time` check appears on any DM rule.

## Schema amendments (amend ADR 0001)

### `dms/{dmId}`

| Field | Type | Notes |
|---|---|---|
| participantUids | List\<String\> | Two UIDs, lexicographic order |
| createdAt | Timestamp | `serverTimestamp()` on first send; no `== request.time` |
| unreadCounts | Map\<String, int\> | `increment(1)` on send, zeroed on open. **Added 0011.** |
| lastMessageText | String? | Preview ≤ 200 chars. **Added 0011.** |
| lastMessageAt | Timestamp? | `serverTimestamp()` on each send; orders list. **Added 0011.** |

### `dms/{dmId}/messages/{messageId}`

| Field | Type | Notes |
|---|---|---|
| messageId | String | Auto-generated, stored redundantly |
| senderUid | String | Must be in `participantUids` |
| senderDisplayName | String | Denormalized from auth state at send time; immutable. **Added 0011.** |
| text | String | Non-empty; ≤ 4 000 chars |
| sentAt | Timestamp | `serverTimestamp()`; no `== request.time`; immutable |
| readBy | List\<String\> | Append-only; initialized to `[senderUid]` |

## Firestore rules

Replaces the existing `match /dms/{dmId}` block in `firestore.rules`.

```
match /dms/{dmId} {
  allow read: if isKmuttUser()
    && request.auth.uid in resource.data.participantUids;

  // areFriends() is NOT called here — it costs 2 get() calls and would exceed
  // the 10-call budget on paths that also evaluate message rules. The friends
  // gate is enforced client-side in ChatRepositoryImpl.sendMessage before any
  // Firestore write is issued.
  allow create: if isKmuttUser()
    && request.auth.uid in request.resource.data.participantUids
    && request.resource.data.participantUids.size() == 2
    && request.resource.data.keys().hasAll([
         'participantUids', 'createdAt', 'unreadCounts'
       ]);

  allow update: if isKmuttUser()
    && request.auth.uid in resource.data.participantUids
    && request.resource.data.diff(resource.data).affectedKeys()
         .hasOnly(['unreadCounts', 'lastMessageText', 'lastMessageAt']);

  allow delete: if false;

  match /messages/{messageId} {
    allow read: if isKmuttUser()
      && request.auth.uid in
         get(/databases/$(database)/documents/dms/$(dmId)).data.participantUids;

    allow create: if isKmuttUser()
      && request.auth.uid in
         get(/databases/$(database)/documents/dms/$(dmId)).data.participantUids
      && request.resource.data.senderUid == request.auth.uid
      && request.resource.data.keys().hasAll([
           'messageId', 'senderUid', 'senderDisplayName', 'text', 'sentAt', 'readBy'
         ])
      && request.resource.data.diff(request.resource.data).affectedKeys()
           .hasOnly([
             'messageId', 'senderUid', 'senderDisplayName', 'text', 'sentAt', 'readBy'
           ]);

    allow update: if isKmuttUser()
      && request.auth.uid in
         get(/databases/$(database)/documents/dms/$(dmId)).data.participantUids
      && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['readBy'])
      && request.auth.uid in request.resource.data.readBy;

    allow delete: if false;
  }
}
```

## Consequences

- ADR 0001 schema amended: `dms/{dmId}` adds `unreadCounts`, `lastMessageText`, `lastMessageAt`; messages adds `senderDisplayName`.
- Declare `dm_conversation_list_viewed`, `dm_conversation_opened`, `dm_message_sent` in `lib/core/analytics_events.dart` before any call site.
- `firestore.rules` `match /dms/{dmId}` replaced in full; `allow update: if false` becomes a restricted field update rule.
- `firestore.indexes.json` must add Index 11 before Messages tab deploys.
- `lib/core/firestore_paths.dart` must add path constants for both collections.
- `dmId` construction enforced in `data/` only; never in the presentation layer.
- Send sequence in `ChatRemoteDatasource.sendMessage` must be two sequential `await` calls — no `WriteBatch`.
- `DmConversationEntity`: `participantUids`, `createdAt`, `unreadCounts`, `lastMessageText`, `lastMessageAt`.
- `DmMessageEntity`: `messageId`, `senderUid`, `senderDisplayName`, `text`, `sentAt`, `readBy`.
- Conversation list: `ListView.builder`; messages paginate 50 at a time via Index 5 + `startAfterDocument`.
- ADR 0004 (Friends) must be fully implemented first. `ChatRepositoryImpl.sendMessage` must read `users/A/friends/B` and `users/B/friends/A` and confirm both have `status == 'accepted'` before issuing any Firestore write; the friends gate is not enforced in rules (budget constraint above).

### `ChatRepository` interface

```dart
abstract interface class ChatRepository {
  Stream<List<DmConversation>> streamConversations(String uid);
  Stream<List<DmMessage>> streamMessages(String dmId, {int limit = 50, DocumentSnapshot? startAfter});

    required String dmId,

    required String text,
  });

```

No Firestore types cross the domain boundary; wrap the `DocumentSnapshot` cursor in an opaque type or replace with a timestamp cursor.

## Reversal plan

- **SD1:** Add `createConversationIfAbsent` (`set()` + `merge: true`) on open; datasource-only.
- **SD2:** Replace map with `dms/{dmId}/unread/{uid}` — amendment ADR, new rules, datasource update, one-time migration.
- **SD3:** Collapse to `WriteBatch` once the SDK resolves the web conflict; datasource-only.
- **SD4:** Switch to `users/{uid}/dmConversations/{dmId}` fanout — amendment ADR, new rules, third write in `sendMessage`, backfill.
- **SD5:** No migration; new sends carry the updated name from auth state after Profile Edit ships.
